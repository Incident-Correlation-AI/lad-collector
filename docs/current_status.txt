Daily Report:
Progress Report: Log Collection & Security Pipeline

Current Status: Six-Domain Collector Complete for Linux; Windows Implemented, Pending Host Validation

What the System Can Do Right Now:

1.  Collects All Six Requested Log Domains

      - authorization: journald (sshd, sudo, PAM, logind, polkit) with
        /var/log/auth.log and /var/log/secure fallbacks.
      - network: journald kernel firewall and NetworkManager/networkd/DHCP/VPN
        messages, with ufw/firewalld file fallbacks.
      - syslog: journald, plus /var/log/syslog, /var/log/messages and
        rsyslog/syslog-ng files when journald is unavailable or
        LAD_SYSLOG_LOG_GLOBS explicitly requests them.
      - service: systemd unit lifecycle and syslog fallbacks.
      - event log: the full Windows Event Log (Application/System/Security);
        audit records arriving through journald are classified as system/audit.
      - database: PostgreSQL, MySQL/MariaDB, MongoDB, Redis, Cassandra,
        Elasticsearch, ClickHouse, PgBouncer and SQL Server log files.

2.  Windows Event Log Support

      - Security, System, Application and firewall channels are subscribed to
        with the modern EvtSubscribe API.
      - A legacy OpenEventLog/ReadEventLog fallback covers Application,
        System and Security when the modern API is unavailable.
      - Optional Sysmon and DNS Client channels; SQL Server and other database
        error logs are tailed from disk.
      - Optional syslog relay files can be configured with
        LAD_SYSLOG_LOG_GLOBS because Windows has no native syslog.
      - Requires Administrator for the Security channel. Access-denied and
        missing channels are reported without stopping the other sources.

3.  Automatic Classification

      - Every event is tagged with one contract category:
        auth, network, syslog, service, system or db.
      - Classification uses deterministic rules: journald identifiers/units,
        message patterns and Windows event IDs/providers.
      - The original source-specific fields are preserved under attributes.

4.  Secret Redaction

      - Messages and nested attribute values are redacted before buffering.
      - Covers passwords, tokens, Authorization/Cookie headers, JWTs, AWS keys,
        PEM private keys, signed URLs and credentials in connection URIs.
      - Redaction is applied twice (reader and final buffer boundary) as
        defense in depth.

5.  Reliable Delivery

      - Size- and time-based batching, a 256 KB batch limit and a bounded
        in-memory buffer.
      - Retries use exponential backoff with jitter; non-retryable 4xx errors
        are dropped and counted instead of looping forever.
      - Partial batch failures are isolated: delivered chunks are counted,
        retryable chunks are requeued, and only rejected chunks are dropped.
      - SIGINT/SIGTERM trigger a graceful drain and a shutdown statistics log.

6.  File Tailing

      - Rotation- and truncation-aware, preserves incomplete final lines, and
        parses JSON logs, common database timestamps, RFC 3164 syslog prefixes
        and audit epoch timestamps.
      - Configurable with LAD_DATABASE_LOG_GLOBS, LAD_SYSLOG_LOG_GLOBS,
        LAD_FILE_TAIL_FROM_START and LAD_LOG_TIMEZONE.

Verification:

  - 33 unit tests pass:
    python3 -m unittest discover -s collectors/tests -t . -v
  - Linux end-to-end delivery was verified against a mock ingestion API using
    real journald events; authorization, network, syslog, service and database
    categories were observed.

Known Gaps / Required Follow-up:

  - Validate the Windows reader as Administrator on a real Windows 11 host.
    The code compiles and was tested with synthetic XML, but the real
    EvtSubscribe/EvtFormatMessage and channel behavior is unverified.
  - Enable Windows Advanced Audit Policy and firewall logging, otherwise
    authorization/network/audit events are not generated by Windows at all.
  - Confirm the backend ingestion schema accepts the category values
    auth/network/syslog/service/system/db and source values such as
    file-syslog-files; extend the enum if it is restricted.
  - Restarts still create a collection gap: sources start at the tail and
    there is no persistent cursor or disk spool yet.
  - File-based syslog/database logs are line oriented; multi-line stack traces
    are emitted as separate events.
  - Event IDs are UUID4, not the UUIDv7 proposed in project_guidelines.txt.

Code Layout (everything is inside collectors/):

  - collectors/linux/          Linux journald and file sources
  - collectors/windows/        Windows Event Log and file sources
  - collectors/app_adapters/   application adapter contract + file tailer
  - collectors/core/engine.py  shared event model, redaction, buffer, delivery
  - collectors/core/classifier.py shared category/type/severity rules
  - collectors/core/runtime.py concurrent source fan-in
  - collectors/main.py         collector entry point (python -m collectors)
  - collectors/tests/          unit tests
  - collectors/tools/          local mock ingestion API
  - collectors/docs/           source coverage + status documentation
  - The simulated/mock event generator was removed from the collector engine.

Documentation:
